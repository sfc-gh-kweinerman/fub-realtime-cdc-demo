The Problem

CDC events from Redpanda need to be matched and merged into a target table in Snowflake. The current architecture lands events via snowflake_streaming into a staging table, then a Dynamic Table performs the MERGE on a 1-minute refresh cycle.

CURRENT Dynamic Table Path

Bottleneck: Dynamic Tables have a minimum 1-minute TARGET_LAG. snowflake_streaming is INSERT-only and cannot target Hybrid Tables.

PROPOSED sql_raw + Hybrid Table

Result: No staging table, no Dynamic Table, no scheduling delay. End-to-end latency under 5 seconds.

Proposed Architecture

Key insight: sql_raw uses a standard SQL driver connection (same as JDBC/ODBC), NOT the Snowpipe Streaming API. This gives it full DML support: MERGE, UPDATE, DELETE against any table type including Hybrid Tables.

Redpanda Connect Configuration

The entire pipeline is a single YAML file. No Python, no Java, no custom consumer application.

Pipeline: Kafka Input + sql_raw MERGE Output

input:
  kafka:
    addresses: ["${REDPANDA_BROKERS}"]
    topics: ["member-cdc-events"]
    consumer_group: "snowflake-merge-consumer"
    batching:
      count: 50
      period: "500ms"

output:
  sql_raw:
    driver: snowflake
    dsn: "${SNOWFLAKE_DSN}"
    queries:
      # Route deletes
      - when: 'this.op == "d"'
        query: |
          DELETE FROM member_master_ht
          WHERE ssn_last4 = ? AND last_name = ?
        args_mapping: |
          root = [this.before.ssn_last4,
                  this.before.last_name]

      # Route inserts/updates via MERGE
      - when: 'this.op == "c" || this.op == "u"'
        query: |
          MERGE INTO member_master_ht AS tgt
          USING (
            SELECT ? AS ssn_last4, ? AS last_name,
                   ? AS email, ? AS phone
          ) AS src
          ON  tgt.ssn_last4 = src.ssn_last4
          AND tgt.last_name = src.last_name
          WHEN MATCHED THEN UPDATE SET
            tgt.email   = COALESCE(src.email, tgt.email),
            tgt.phone   = COALESCE(src.phone, tgt.phone),
            tgt.updated_at = CURRENT_TIMESTAMP()
          WHEN NOT MATCHED THEN INSERT
            (member_id, ssn_last4, last_name,
             email, phone, updated_at)
            VALUES
            (member_seq.NEXTVAL, src.ssn_last4,
             src.last_name, src.email, src.phone,
             CURRENT_TIMESTAMP())
        args_mapping: |
          root = [this.after.ssn_last4,
                  this.after.last_name,
                  this.after.email,
                  this.after.phone]
    max_in_flight: 4

Key Configuration Points

  • Conditional queries: CDC events are routed to DELETE or MERGE based on the op field.
  • Batching: Flush every 500ms or 50 messages, whichever comes first.
  • Parallelism: max_in_flight: 4 allows concurrent processing across Redpanda partitions while preserving ordering within each partition.
  • COALESCE: Partial updates only overwrite non-null fields, preserving existing data.
  • Partition key: Partition by your MERGE match key to guarantee ordering per entity.
